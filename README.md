# Студия маникюра — шаблон с онлайн-записью

Сайт для nail-мастера или небольшой студии: услуги и цены, работы, мастера,
онлайн-запись по реально свободным окнам, контакты. Плюс кабинет мастера (`/#/admin`).

```bash
npm install
npm run dev      # http://localhost:5190, кабинет — http://localhost:5190/#/admin
npm run build
```

## Дизайн LUMI 2.0 («Soft Precision»)

- Шрифты — два: **Tenor Sans** (название студии и крупные заголовки) и **Onest** (меню, цены, текст, формы, кабинет).
  Оба свои (`@fontsource`, woff2 с кириллицей), без внешних CDN; страница не ждёт шрифтов, запасной — без засечек.
- Палитры — три готовые (`theme.preset`): `mulberry` (Шелковица, демо LUMI), `taupe` (Тёплый тауп), `rose` (Пыльная роза).
  `theme.accent` — свой тёмный акцент вместо цвета палитры; слишком светлый затемняется сам до читаемого. Цвета — `src/lib/theme.ts`.
- Первый экран (`src/site/Top.tsx`): название студии как вёрстка + одно фото работы + полоса «Адрес / Отзывы / Запись».
  Размер названия считается по его ширине (`src/site/useWordmark.ts`): короткое (LUMI, БЛИК) — крупно, и фото начинается
  там, где кончаются буквы; длиннее — во всю строку; очень длинное — аккуратный логотип, крупным становится заголовок.
  Вертикальное фото — своя раскладка (текст | фото | колонка фактов). Без фото — текстовый вариант на тёмном поле.
- Код: `src/design/` — токены и база, `src/site/` — разделы сайта и их стили. Кабинет — `src/admin/`, общие стили кабинета — `src/styles.css`.

## Как сделать сайт под нового клиента

1. `src/data/demo.ts` — всё содержимое. То же можно поменять в кабинете → «Студия», «Услуги», «Работы», «Отзывы», «График».
   - `theme` — `preset` (палитра) и необязательный `accent` (свой тёмный акцент).
   - `studio.heroTitle` / `heroLead` — заголовок первого экрана (пусто — «Маникюр и педикюр»).
   - `studio.heroPhoto` — главное фото первого экрана: работа крупным планом, без надписей. Нет — берётся главная работа.
     `heroPositionDesktop` / `heroPositionMobile` — точка кадра; `heroLayout: 'typographic'` — первый экран без фото.
   - `studio.booking` — `{ mode: 'native' }` (запись на сайте) или `{ mode: 'external', url, name: 'DIKIDI' }`:
     тогда все кнопки «Записаться» ведут в сервис студии, своей сетки времени на сайте нет.
   - `works[].focus` — необязательная точка кадра (`'50% 30%'`), если на снимке ногти не по центру.
   - `masters[]` — `photo`: **настоящая фотография мастера, если она есть у клиента** (стоковые и чужие фото — нельзя);
     только если фото нет — вместо него показываются три работы этого мастера. Дальше: `years` (стаж — только подтверждённый),
     `portfolio` (ссылка), `serviceIds`. Один мастер — блок «Мастер» и выбор мастера в записи подстраиваются сами.
   - `studio.routeUrl` — своя ссылка «Маршрут» (например, карточка в 2ГИС); нет — маршрут в Яндекс Картах по координатам `map`.
   - `studio.reviewsSource` — `{ name, url, rating?, count? }`: карточка с отзывами на картах. Только настоящие цифры;
     без ссылки на первом экране — переход к отзывам на сайте, без оценки — просто ссылка «Отзывы в …».
   - `reviews[]` — `rating`, `source`, `url`, `featured` необязательны: звёзды и источник показываются только если заполнены.
     `demo: true` — пример для демо-сайта (на сайте помечен «пример для демо»); у клиента — только настоящие отзывы без этого флага.
   - `studio.demoNote` — пометка в подвале для демо («студия вымышлена, фото — Unsplash»). У настоящей студии — пусто.
2. Фото: загрузить с телефона/компьютера в кабинете (кнопка «Загрузить с устройства», в «Работах» — сразу несколько),
   или id снимка Unsplash (`photo-…`), или ссылка/путь (`/photos/hero.jpg` из `public/`). Пропорции любые.
   Загруженные фото сжимаются (до 1600 px) и пока хранятся в браузере (IndexedDB, `src/lib/media.ts`) — как и все данные демо;
   для боевой версии их нужно загружать на сервер.
3. Для настоящей студии выключить «Демо: заполнять расписание выдуманными записями» (кабинет → Студия).

Галерея раскладывается сама (`src/lib/gallery.ts`) полосами по 12-колоночной сетке (крупный снимок + стопка, тройка
разной ширины, пара 7:5) — ровно при любом числе работ, без повторов и одиночных хвостов. Фильтры «Мастер» и «Стиль»
показывают только то, что есть у работ.

## Приложение на телефоне и уведомления

В кабинете — кнопка «Подключить уведомления» и гайд (iPhone / Android, платформа определяется сама):
как поставить кабинет на рабочий стол и разрешить уведомления. На iPhone уведомления от сайта работают
только у приложения с экрана «Домой» (iOS 16.4+); на Android — и в браузере, но приложение надёжнее.

- `public/manifest.webmanifest` (сайт) и `public/admin.webmanifest` (кабинет: открывается сразу в кабинете),
  иконки `public/icon-*.png`, `apple-touch-icon.png`. Под нового клиента — поменять имя в манифестах и иконку.
- `public/sw.js` — сервис-воркер: показывает уведомления (в т.ч. пуш с сервера) и открывает кабинет по нажатию.
- `src/lib/push.ts` — установка, разрешение, подписка; `src/notify/Guide.tsx` — гайд (для мастера и для клиентки);
  `src/admin/Notify.tsx` — кнопка в кабинете; `src/notify/Remind.tsx` — напоминания клиентке.
- Без сервера кабинет сам показывает «Новая запись: …», пока он открыт на этом устройстве.

### Напоминания клиентке — за 24, 12, 3 и 1 час

- На экране «вы записаны» — карточка «Напомнить о визите?». Android и компьютер: одно нажатие → «Разрешить».
  iPhone: гайд «на экран „Домой“»; в приложении внизу появляется «Включить напоминания» — клиентка вводит телефон,
  с которым записывалась (у приложения на iPhone своё хранилище, запись из Safari оно не видит).
- «В календарь» (.ics) — четыре напоминания календаря телефона, работают без сервера и без установки.
- Часы — `studio.reminders` (по умолчанию `[24, 12, 3, 1]`), часовой пояс студии — `studio.timezone`.

### Сервер уведомлений (`server/`)

Node 18+, одна зависимость (`web-push`), данные — один JSON-файл. Одна установка обслуживает много студий:
адрес студии — `https://<сервер>/s/<студия>`.

Боевой сервер — zapisvonline.ru (там же «Север Авто», веб-сервер Caddy). Каждая студия — свой поддомен
(`lumi.zapisvonline.ru`), чтобы у сайтов не смешивались приложения на телефоне, вход и данные браузера.
`deploy/setup.sh` ставит сервер уведомлений службой (systemd), создаёт ключи VAPID и добавляет поддомен в Caddy,
не трогая существующие сайты (проверяет конфиг и откатывает, если что-то не так). Нужна DNS-запись `*.zapisvonline.ru → 82.146.59.186`. Мастеру — пуш о новой онлайн-записи; клиентке — напоминания
по расписанию (если записалась за 2 часа — придёт только «через час»); отменённой записи не напоминает.

```bash
cd server && npm install
npm run keys                     # ключи VAPID, один раз
cp .env.example .env             # вписать ключи, ALLOWED_ORIGINS — адрес сайта
node --env-file=.env index.mjs   # или pm2 / systemd; снаружи — через nginx с https
npm test
```

На сайте: `studio.push = { vapidPublicKey: '<публичный ключ>', server: 'https://<сервер>/s/lumi' }`.
Сайт сам отправляет на сервер новые записи и отмены (`src/lib/store.ts`). Пока записи живут в браузере,
сервер знает только о записях с сайта и из кабинета на том же устройстве — полноценно это заработает вместе
с общим хранилищем записей на сервере.

## Устройство

- `src/lib/theme.ts` — тема студии → CSS-переменные (`--accent`, `--paper`, `--ink`, `--nail`); контуры форм ногтя.
- `src/lib/slots.ts` — движок свободного времени («любой мастер» = кто свободен).
- `src/lib/store.ts` — данные и записи. Сейчас хранятся в браузере (localStorage) — для демо.
  Запись перепроверяет окно перед сохранением, как это делает сервер.
- `src/lib/contact.ts` — телефон или ник в Telegram. `src/lib/ui.tsx` — фото, `typo()` (неразрывные пробелы после коротких слов).
- `src/site/` — `Top` (шапка, первый экран), `Showcase` (цены, работы, мастера), `Booking` (запись), `Bottom` (отзывы, контакты).
- `src/admin/` — кабинет: записи, ручная запись, график и отпуска, услуги, работы, отзывы, тема и тексты.
- Стили сайта: `src/design/tokens.css`, `src/design/base.css`, `src/site/*.css`. Анимации — CSS и IntersectionObserver,
  без библиотек; `prefers-reduced-motion` их выключает.
- Время: «сегодня» и прошедшие окна считаются по часам студии (`studio.timezone`), а не браузера; `.ics` — в UTC.

## Что нужно до боевого запуска

Честно: **сейчас запись на сайте — демо.** На сайте это написано («Демо-режим…») для демо-сайтов.

- Сервер: записи сейчас живут в браузере, мастер не увидит записи клиента с другого устройства.
  Нужен общий API записей: проверка окна на сервере (график, длительность, перерыв, отпуск) и атомарный захват слота
  (две клиентки на одно время), отмены и ручные записи — только с входом мастера, отдельные данные каждого салона.
  Нужно подключить `store.ts` к API (подойдёт сервер shina-booking: Hono + PostgreSQL, логика слотов та же)
  и закрыть кабинет паролем.
- Уведомления мастеру о новой записи (Telegram-бот) и напоминания клиенту — со стороны сервера.
- Фото: демо берёт снимки с Unsplash по ссылке. Для клиента — его собственные фото в `public/`
  (внешние CDN из РФ могут открываться медленно).
- Отзывы в демо — примеры текста. Публиковать только настоящие.
